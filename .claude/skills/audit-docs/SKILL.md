# audit-docs

Surveys Markdown documentation and emits a findings list. Does not modify, delete, or commit anything — that's a downstream decision.

Two scopes:

- **Broad** (default): every `.md` file in the repo, checked against current code reality. Surfaces drift, low-value content, and clarity issues.
- **Diff-scoped**: docs checked against a specific commit, PR, or commit range. Surfaces drift introduced by the change and missing coverage for new APIs/flags/conventions.

## Severity scheme

| Severity | Category | Examples |
|---|---|---|
| **misleading** | Doc drift | References to deleted features, renamed flags, missing files, behavior that no longer matches code |
| **low-value** | Clutter | Stubs, duplicates, culture-drift docs, unfulfilled formalities (e.g. CHANGELOG with 3 stale entries), unrepairable drift |
| **clarity** | Readability / missing coverage | Verbose/wall-of-text sections; buried install/usage; undefined acronyms; ambiguous pronouns; *or*, in diff scope: new public API, config option, or convention without docs |

`misleading` is highest. In diff scope, `low-value` rarely applies — a diff doesn't make existing docs low-value — and is typically skipped.

## What to skip

- Auto-generated files (CHANGELOG if generated by tooling, files in `target/`, `node_modules/`, `dist/`, `.git/`)
- ADRs (`docs/adr/`, `**/docs/adr/`)
- Non-Markdown files
- AI instruction files (`CLAUDE.md`, `.cursorrules`, etc.) in **broad** scope — different purpose, different quality bar. **Include** them in diff scope, since code changes can drift them too.

## Workflow

### 1 — Determine scope

If the user specified a diff (commit, PR number, commit range, "since main", "the last two commits"), resolve it from conversation context and fetch the diff. Otherwise, default to broad scope. If a diff is requested but every changed file is `.md`, exit early: "no code changes — nothing to sync."

If the user specified a path, file, or glob, narrow broad-scope to that subset.

### 2 — Load domain model

Invoke /read-domain to ground the audit in canonical vocabulary. Domain terms help judge whether docs use the right language and whether renamed concepts constitute drift.

### 3 — Establish ground truth

- **Broad**: explore the repo to detect drift against main modules/packages, commands/APIs/flags, tooling (CI, build system, package manager).
- **Diff-scoped**: list what changed — added/removed/renamed functions, commands, flags, files, config options, conventions.

### 4 — Audit

- **Broad**: scan each `.md` file for findings in all three severities. Quote the exact passage that triggers each finding.
- **Diff-scoped**: for each change, hunt across all `.md` files (including AI instruction files) for docs that reference the old name or should mention the new one.

| Diff change | Look for docs that... |
|---|---|
| Function/command/flag added, removed, or renamed | mention the old name, or should mention the new one |
| File/module moved or deleted | reference the old path |
| Config option added, removed, or renamed | mention it (README, config docs, CLAUDE.md) |
| New public API item added | should document it but don't |
| CI/config change affecting user-facing behavior | describe that behavior |
| New test convention or macro | are referenced in CLAUDE.md or contributing docs |

### 5 — Emit findings

Print a numbered list, grouped by severity (misleading → low-value → clarity). For each finding:

```
N. [severity] file:line — short label
   Quote: "<exact passage from the doc>"   # omit for missing-coverage findings
   Issue: <what's wrong / what's missing>
   Recommendation: <fix / delete / merge / rewrite / clarify / write doc at suggested file>
```

End with a one-line summary: total findings, breakdown by severity. Do not modify any file.

## Principles

- **When in doubt, flag — don't fix.** This skill's job is to surface, not act.
- **Quote, don't paraphrase.** Each finding cites the exact passage so the user can locate and judge it.
- **Don't invent missing content.** Note where content is missing, but the user fills the gap.
- **Diff scope stays narrow.** Don't sweep the whole repo for unrelated drift when given a diff.
- **Recommendations are non-binding.** A suggestion the user may overrule.
